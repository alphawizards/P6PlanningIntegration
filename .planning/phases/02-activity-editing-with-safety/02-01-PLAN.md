Create `src/automation/activity_editor.py` with class `P6ActivityEditor`.

**Constructor:**
- Takes `main_window` (P6 main window wrapper) and `activity_manager` (P6ActivityManager instance for select_activity)
- Sets `safe_mode` flag (default True, same pattern as P6ActivityManager)
- Constants: `DIALOG_TIMEOUT = 10`, `ACTION_DELAY = 0.3`, `VERIFY_DELAY = 0.5`

**Helper: `_get_details_pane()`**
- Locate the Details Form bottom pane: `self._window.child_window(control_type="Pane", found_index=1)`
- Return the pane wrapper
- This is a best-effort locator -- exact control identification may vary in P6 20 (Java Swing via UIA). Log warnings if not found.

**Helper: `_select_details_tab(tab_name: str) -> bool`**
- Get details pane via `_get_details_pane()`
- Find tab control: `details_pane.child_window(control_type="Tab")`
- Call `tab_control.select(tab_name)`
- Sleep `ACTION_DELAY`
- Return True on success, False on failure
- IMPORTANT: Always call this before EVERY edit operation -- tab state may not persist across activity selections (Pitfall 3 from research)

**Helper: `verify_edit(control, expected_value: str) -> bool`**
- Sleep `VERIFY_DELAY` (give P6 time to process -- Pitfall 4 from research)
- Read value back: try `control.get_value()`, fall back to `control.window_text()`
- Compare with expected_value (strip whitespace from both)
- If match: log success, return True
- If mismatch: log error with both expected and actual values, return False
- Do NOT retry -- per user decision, report failure immediately

**Method: `edit_start_date(activity_id: str, new_date: str) -> bool`**
- Check safe_mode
- Select activity via `self._activity_manager.select_activity(activity_id)` -- fail if not found
- Call `_select_details_tab("Dates")` -- fail if tab not found
- Find start date field: `details_pane.child_window(control_type="Edit", title_re=".*Start.*")`
- Set focus on field, clear it (`set_text("")`), type new_date using `type_keys(new_date, with_spaces=False)`, press Enter (`type_keys("{ENTER}")`)
- Call `verify_edit()` with the field and new_date
- Date format is DD-MMM-YY (e.g., "15-Mar-26") -- do NOT convert or validate format here, pass through as-is
- Return True if verified, False if rejected

**Method: `edit_finish_date(activity_id: str, new_date: str) -> bool`**
- Same pattern as edit_start_date but find finish date field: `title_re=".*Finish.*"`
- Check safe_mode, select activity, switch to Dates tab, edit, verify

**Method: `edit_duration(activity_id: str, new_duration: int, use_details_form: bool = True) -> bool`**
- Check safe_mode
- Select activity via activity_manager
- If `use_details_form=True` (default):
  - Switch to "Status" tab in Details Form
  - Find Remaining Duration field: `title_re=".*Remaining.*Duration.*|.*Remaining.*Dur.*"`
  - Clear and type str(new_duration), press Enter
  - Verify edit
- If `use_details_form=False`:
  - Log warning that grid editing for durations is less reliable
  - Use `_window.type_keys("{F2}")` to enter edit mode on current cell
  - Select all (`^A`), type duration, Enter
  - Verification is harder in grid mode -- log that verification is best-effort
- Return True if verified, False otherwise
- Note: For "Not Started" activities, changing Remaining Duration auto-updates Original Duration. This is expected P6 behavior -- do not treat as an error.

**Error handling pattern (apply to all methods):**
- Wrap in try/except
- Catch `P6SafeModeError` and re-raise
- Catch all other exceptions, log error with full message, return False
- Do NOT use retry loops (Phase 1 decision 01-01-D2)
- Import `P6SafeModeError` from `.exceptions`

- `logger` from `src.utils`
- `P6SafeModeError` from `.exceptions`
