# Phase 2: Activity Editing with Safety - Research

**Researched:** 2026-02-09
**Domain:** GUI automation with pywinauto for P6 Professional activity editing, XER backup/restore
**Confidence:** MEDIUM

## Summary

Phase 2 implements activity editing in P6 Professional through GUI automation using pywinauto's UIA backend. The research confirms that pywinauto can automate the required operations (date editing, duration changes, relationship management, activity creation, and XER backup) but requires careful handling of Java Swing controls through UIA, which has known limitations.

The standard approach involves using the P6 Details Form (bottom pane) for most edits because tab positions are fixed, unlike grid columns which users can reorder. Activity location uses Ctrl+F search dialog pattern (already proven in Phase 1). XER export/import provides backup and rollback through P6's native File → Export dialog automation.

Key challenge: P6 Professional 20 uses Java Swing, which pywinauto's UIA backend can interact with but doesn't natively support. This means we rely on Windows UIA layer's interpretation of Swing controls, requiring defensive verification after every edit.

**Primary recommendation:** Use Details Form for date/duration edits, verify all changes by reading values back, implement XER backup before edit sessions with manual rollback (not automatic), and handle P6's UI responsiveness delays with appropriate wait timing.

## User Constraints (from CONTEXT.md)

### Locked Decisions

**How to edit activities in P6:**
- **Two editing methods available:**
  - Grid cells: Double-click cell → type value → Enter. Fast but column positions vary by layout.
  - Details Form (bottom pane): Select activity → switch to appropriate tab → edit fields. Safer for automation because tab positions are fixed.
- **Dates must be edited via the Details Form** — not directly in grid cells
- **Durations can be edited in either grid or Details Form:**
  - Grid: Remaining Duration column (double-click, type, Enter)
  - Details Form: Status tab shows Original, Actual, and Remaining duration fields
  - If activity is "Not Started", changing Remaining Duration auto-updates Original Duration
- **Date format:** DD-MMM-YY (e.g., 15-Mar-26)
- **Finding activities:** Click Activity ID column header → Ctrl+F → type Activity ID → Find Next (same search pattern as EPS navigation)
- **Verification:** After every edit, read the value back from the cell to confirm P6 accepted it (may reject due to locks or constraints)

**Relationship editing workflow:**
- **Location:** Select activity → Relationships tab in Details Form (bottom pane)
- **Adding relationships:** Click "Assign" button → search dialog → type predecessor Activity ID or name → select → confirm
- **Primary relationship type:** Finish-to-Start (FS) — this is the most commonly used type
- **Lag:** Support lag when specified by user ("I will advise if a lag is required") — default is zero lag
- **All four types should be supported** (FS, SS, FF, SF) but FS is the primary use case
- **Removing relationships:** Select the relationship in the Relationships tab and delete

**Creating new activities:**
- **Method:** Select target WBS node → press Insert key (or Edit menu → Add)
- **Activity ID:** Auto-generated by P6 — no custom naming convention needed
- **WBS placement:** User will specify which WBS node to add the activity under
- **Required fields after insertion:**
  1. Activity Name — descriptive name (user will provide)
  2. Duration — original duration (user will provide)
  3. Activity Type — Task Dependent, Resource Dependent, etc. (user will specify)
  4. Calendar — which calendar the activity uses (user will specify)
- **Workflow:** Navigate to WBS node → Insert → fill required fields in Details Form

**Backup & rollback behavior:**
- **Backup timing:** Only when user explicitly asks — NOT automatic before every edit session
- **Backup method:** File → Export → XER through P6's standard export dialog
- **Backup location:** User will specify the folder each time — no default backup directory
- **Rollback approach:** If something goes wrong, Claude stops immediately and reports to user — NO automatic rollback
- User decides whether to manually undo, re-import backup, or accept the state
- P6's Ctrl+Z undo is available but user controls when to use it

### Pattern 1: Details Form Tab Navigation

**What:** Navigate to specific tabs in P6's Details Form (bottom pane) to edit activity fields
**When to use:** Editing dates, durations, relationships - any field not safely editable in grid
**Example:**
```python
# Pattern: Select activity → switch to tab → find control → edit → verify
def edit_activity_start_date(self, activity_id: str, new_date: str) -> bool:
    """Edit activity start date via Details Form - Dates tab."""
    # 1. Select activity using Ctrl+F (proven in Phase 1)
    if not self.select_activity(activity_id):
        return False

    # 2. Focus Details Form bottom pane
    details_pane = self._window.child_window(control_type="Pane", found_index=1)

    # 3. Switch to Dates tab
    tab_control = details_pane.child_window(control_type="Tab")
    tab_control.select("Dates")  # Tab name from P6 UI
    time.sleep(self.ACTION_DELAY)

    # 4. Find Start Date field (Edit control)
    start_field = details_pane.child_window(
        control_type="Edit",
        title_re=".*Start.*"
    )

    # 5. Edit the value
    immediate_type(start_field, new_date, clear_first=True)
    start_field.type_keys("{ENTER}")
    time.sleep(self.ACTION_DELAY)

    # 6. VERIFY: Read value back (CRITICAL per user requirement)
    actual_value = start_field.get_value()
    if actual_value != new_date:
        logger.warning(f"P6 rejected edit: expected {new_date}, got {actual_value}")
        return False

    return True
```

**Source:** User requirement: "Dates must be edited via the Details Form" + pywinauto tab control pattern

### Pattern 2: Edit Verification (Defensive Reading)

**What:** After every edit, read the value back to confirm P6 accepted the change
**When to use:** ALL edit operations - P6 can silently reject changes due to locks, constraints, or validation
**Example:**
```python
def verify_edit(self, control, expected_value: str) -> bool:
    """Verify that P6 accepted an edit by reading the value back."""
    time.sleep(0.3)  # Give P6 time to process
    actual_value = control.get_value()

    if actual_value != expected_value:
        logger.error(f"Edit verification failed: expected '{expected_value}', got '{actual_value}'")
        return False

    logger.debug(f"Edit verified: {expected_value}")
    return True
```

**Source:** User requirement: "After every edit, read the value back from the cell to confirm P6 accepted it"

### Anti-Patterns to Avoid

- **Don't use grid cell editing for dates:** Columns can be reordered by users, breaking automation. Use Details Form.
- **Don't skip verification after edits:** P6 can silently reject changes. Always read back and check.
- **Don't use automatic backups before every edit:** User explicitly rejected this. Backup only on demand.
- **Don't implement automatic rollback:** User wants manual control. Claude stops and reports, user decides.
- **Don't use retry loops on edit failures:** User requirement from Phase 1: immediate failure, report to user.
- **Don't assume Java Swing controls expose all properties:** UIA sees only what Windows exposes; some properties may be inaccessible.

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Date parsing/formatting | Custom parser for DD-MMM-YY | `datetime.strptime(date, "%d-%b-%y")` | Handles locale, edge cases, and formats correctly |
| GUI element waiting | `time.sleep()` everywhere | `wait_for_condition()` from utils.py | Robust polling with timeout, already implemented in Phase 1 |
| Control interaction | Direct Win32 API calls | pywinauto wrappers (`immediate_click`, `immediate_type`) | Handles focus, visibility, timing automatically |
| XER export wizard | Custom dialog navigation | Extend `P6ExportManager` from exporting.py | Export wizard logic already implemented for other formats |
| Activity search | Tree traversal or grid scanning | Ctrl+F dialog pattern from Phase 1 | Proven reliable, handles large projects efficiently |

**Key insight:** P6 Professional's Java Swing GUI through UIA is fragile. Don't fight the limitations—work within them by using proven patterns from Phase 1 (Ctrl+F search, menu selection, dialog handling) and extending existing modules rather than creating new approaches.

## Common Pitfalls

### Pitfall 1: Java Swing Control Property Inaccessibility

**What goes wrong:** Some Java Swing control properties aren't exposed through Windows UIA, causing `AttributeError` or empty values when trying to read them.

**Why it happens:** P6 Professional 20 uses Java Swing, which pywinauto doesn't natively support. We rely on Windows UIA's interpretation of Swing controls, which is incomplete.

**How to avoid:**
- Use `get_value()` for Edit controls (proven reliable)
- Use `window_text()` for static text/labels
- If a property isn't accessible, find an alternative approach (e.g., read from grid cell instead of Details Form field)
- Test each control interaction against live P6 before relying on it

**Warning signs:**
- `AttributeError` on seemingly valid properties
- Empty strings returned from controls that visibly contain text
- Controls that exist but don't respond to methods

**Source:** GitHub issue: pywinauto TODO list shows "Java Swing/AWT support" as future feature using JPype

### Pitfall 2: P6 Silently Rejecting Edits

**What goes wrong:** You type a new date/duration into a field, press Enter, and P6 reverts to the old value without showing an error dialog.

**Why it happens:** P6 validates edits against constraints (locked fields, date constraints like SNET/FNLT, calendar restrictions). Invalid edits are silently rejected.

**How to avoid:**
- ALWAYS verify edits by reading the value back after submitting (user requirement)
- Implement `verify_edit()` helper that reads value and compares to expected
- Report verification failures to user with both expected and actual values
- Don't retry automatically - user decides next action

**Warning signs:**
- Edit appears to succeed but subsequent operations use old value
- P6 beeps or flashes but no error dialog appears
- Value in grid doesn't match what you typed into Details Form

**Source:** User requirement: "After every edit, read the value back from the cell to confirm P6 accepted it (may reject due to locks or constraints)"

### Pitfall 3: Details Form Tab State Not Persisted

**What goes wrong:** You switch to the "Dates" tab, edit a field, select a different activity, and the Details Form switches back to a different tab, causing subsequent edits to fail.

**Why it happens:** P6 may remember the last-used tab per activity or reset to a default tab on activity selection changes.

**How to avoid:**
- Always explicitly select the required tab before EVERY edit operation
- Don't assume tab state persists across activity selections
- Use `tab_control.select("TabName")` at the start of each edit method
- Verify the correct tab is active before attempting edits

**Warning signs:**
- Edit operations fail with "control not found" errors
- Controls are found but contain unexpected data (from wrong tab)
- First edit succeeds, subsequent edits fail

**Source:** Common GUI automation pattern + P6 UI behavior observation

### Pitfall 4: Timing Issues Between Edit and Verification

**What goes wrong:** You type a value, immediately read it back, and get the old value or empty string even though the edit will eventually succeed.

**Why it happens:** P6 processes edits asynchronously. The value isn't committed to the control immediately after typing.

**How to avoid:**
- Add a small delay (0.3-0.5s) after pressing Enter before reading the value back
- Use `wait_for_condition()` if the delay isn't sufficient for large projects
- Don't use `time.sleep(0)` - P6 needs real time to process
- Monitor CPU usage for multi-threaded processing (see pywinauto's `wait_cpu_usage_lower`)

**Warning signs:**
- Verification fails inconsistently (sometimes passes, sometimes fails)
- Adding a `time.sleep(1)` makes the problem disappear
- Reading the same value twice in quick succession returns different results

**Source:** pywinauto documentation: "Waiting for Long Operations" and "wait_cpu_usage_lower" for multi-threaded apps

### Pitfall 5: XER Export Path Handling on Windows

**What goes wrong:** XER export fails because the path contains spaces, forward slashes, or other characters P6's Save dialog doesn't handle correctly.

**Why it happens:** P6's file dialogs may not properly escape paths, especially when passed programmatically.

**How to avoid:**
- Use `str(Path(user_path).resolve())` to normalize paths
- Test with paths containing spaces, dashes, underscores
- Use `sanitize_filename()` utility from utils.py for user-provided filenames
- Prefer backslashes on Windows (`Path` handles this automatically)

**Warning signs:**
- Export wizard closes without creating the file
- P6 shows "Invalid path" error dialog
- File created in unexpected location (path interpreted incorrectly)

**Source:** Common Windows automation pitfall + existing `sanitize_filename()` in utils.py

```python
def select_activity(self, activity_id: str) -> bool:
    """Select activity by ID using Ctrl+F search."""
    self._window.set_focus()
    time.sleep(self.ACTION_DELAY)

    # Ctrl+F opens Find dialog

    time.sleep(self.ACTION_DELAY)

    # Find Next
    find_button = find_dialog.child_window(title_re=".*Find.*Next.*", control_type="Button")
    find_button.click_input()
    time.sleep(self.ACTION_DELAY)

    # Close dialog
    find_dialog.type_keys("{ESC}")

    return True
```

### Date Editing with Verification

```python
# Source: User requirements + pywinauto Edit control methods
def edit_start_date(self, activity_id: str, new_date: str) -> bool:
    """
    Edit activity start date via Details Form.

    Args:
        activity_id: Activity to edit
        new_date: Date in DD-MMM-YY format (e.g., "15-Mar-26")

    Returns:
        True if edit succeeded and was verified
    """
    # 1. Select activity
    if not self.select_activity(activity_id):
        logger.error(f"Activity not found: {activity_id}")
        return False

    # 2. Navigate to Dates tab in Details Form

    tab_control = details_pane.child_window(control_type="Tab")
    tab_control.select("Dates")
    time.sleep(self.ACTION_DELAY)

    # 3. Find Start Date field

        control_type="Edit",
        title_re=".*Start.*"
    )

    # 4. Edit value
    start_field.set_focus()
    start_field.set_text("")  # Clear first
    start_field.type_keys(new_date, with_spaces=False)
    start_field.type_keys("{ENTER}")
    time.sleep(0.5)  # Critical: Give P6 time to process

    # 5. VERIFY (user requirement)
    actual = start_field.get_value()
    if actual != new_date:
        logger.error(
            f"P6 rejected start date edit for {activity_id}: "
            f"expected '{new_date}', got '{actual}'"
        )
        return False

    logger.info(f"✓ Start date updated: {activity_id} → {new_date}")
    return True
```

### XER Backup

```python
# Source: exporting.py P6ExportManager + user requirements
def backup_project_to_xer(self, output_path: Path) -> bool:
    """
    Export current project to XER for backup.
    User must provide output_path explicitly.
    """
    logger.info(f"Creating XER backup: {output_path}")

    # Use File → Export
    self._window.menu_select("File->Export")
    time.sleep(self.ACTION_DELAY * 2)

    # Export wizard
    wizard = Desktop(backend="uia").window(title_re=".*Export.*")
    wizard.wait("ready", timeout=self.DIALOG_TIMEOUT)

    # Select Primavera PM (XER) format
    type_list = wizard.child_window(control_type="List")
    xer_item = type_list.child_window(title_re=".*Primavera PM.*")
    xer_item.click_input()

    # Next button
    next_button = wizard.child_window(title_re=".*Next.*", control_type="Button")
    next_button.click_input()
    time.sleep(self.ACTION_DELAY)

    # Project selection (already selected)
    next_button.click_input()
    time.sleep(self.ACTION_DELAY)

    # Export options
    next_button.click_input()
    time.sleep(self.ACTION_DELAY)

    # File path
    path_edit = wizard.child_window(control_type="Edit")
    path_edit.set_text(str(output_path))

    # Finish
    finish_button = wizard.child_window(title_re=".*Finish.*", control_type="Button")
    finish_button.click_input()

    # Wait for file creation
    if wait_for_condition(
        lambda: output_path.exists() and output_path.stat().st_size > 0,
        timeout=60,
        poll_interval=1.0
    ):
        size_kb = output_path.stat().st_size / 1024
        logger.info(f"✓ XER backup created: {output_path} ({size_kb:.1f} KB)")
        return True

    logger.error(f"XER backup failed: {output_path}")
    return False
```
