  <action>
Create `src/automation/relationships.py` with class `P6RelationshipManager`.

**Constructor:**
- Takes `main_window` and `activity_manager` (P6ActivityManager instance)
- Sets `safe_mode` flag (default True)
- Constants: `DIALOG_TIMEOUT = 10`, `ACTION_DELAY = 0.3`
- Valid relationship types: `VALID_REL_TYPES = ("FS", "SS", "FF", "SF")`

**Helper: `_get_details_pane()` and `_select_details_tab(tab_name)`**
- Same pattern as activity_editor.py (locate bottom pane, select tab)
- Duplicate is acceptable -- these are small helpers and shared base class would be premature optimization

**Method: `add_predecessor(activity_id: str, predecessor_id: str, rel_type: str = "FS", lag: int = 0) -> bool`**
- Check safe_mode
- Validate rel_type is in VALID_REL_TYPES, raise ValueError if not
- Select the target activity via `self._activity_manager.select_activity(activity_id)`
- Switch to "Relationships" tab in Details Form via `_select_details_tab("Relationships")`
- Click "Assign" button: `details_pane.child_window(title="Assign", control_type="Button")` -- use `immediate_click()`
- Wait for Assign dialog: `Desktop(backend="uia").window(title_re=".*Assign.*")` with `.wait("ready", timeout=DIALOG_TIMEOUT)`
- In the Assign dialog:
  - Find search edit: `search_dialog.child_window(control_type="Edit", found_index=0)`
  - Type predecessor_id using `immediate_type()`
  - Click "Search" or "Find" button: `search_dialog.child_window(title_re=".*Search.*|.*Find.*", control_type="Button")`
  - Wait ACTION_DELAY for results
  - Select the result (first item in list or the found activity)
  - Click "Assign" or "OK" button to confirm: `search_dialog.child_window(title_re=".*Assign.*|.*OK.*", control_type="Button")`
  - Close dialog if still open
- After assignment, if rel_type is not "FS" or lag != 0:
  - The relationship now appears in the Relationships tab grid
  - Find the newly added row (last row or search for predecessor_id)
  - Edit the Type column: double-click the cell, select rel_type from dropdown or type it
  - Edit the Lag column: double-click the cell, type lag value, press Enter
  - NOTE: The exact mechanism for editing rel_type and lag in the Relationships tab grid needs live P6 inspection (Open Question 2 from research). Implement the most likely pattern (double-click cell, type value, Enter) and log clearly if it fails.
- Log success: `"Added relationship: {predecessor_id} -> {activity_id} ({rel_type}, lag={lag})"`
- Return True on success

**Method: `remove_predecessor(activity_id: str, predecessor_id: str) -> bool`**
- Check safe_mode
- Select the target activity
- Switch to "Relationships" tab
- Find the predecessor in the relationships grid:
  - Look for text matching predecessor_id in the grid rows
  - Try: `details_pane.child_window(title_re=f".*{predecessor_id}.*")` to locate the row
  - Click to select it
- Delete the relationship:
  - Try "Remove" button first: `details_pane.child_window(title_re=".*Remove.*|.*Delete.*", control_type="Button")`
  - If no button found, try Delete key: `self._window.type_keys("{DELETE}")`
  - Handle confirmation dialog if one appears (click Yes/OK)
- Log success and return True

**Method: `add_successor(activity_id: str, successor_id: str, rel_type: str = "FS", lag: int = 0) -> bool`**
- This is semantically equivalent to `add_predecessor(successor_id, activity_id, rel_type, lag)`
- Call add_predecessor with swapped arguments
- Adjust logging to say "Added successor"

**Error handling (same pattern as activity_editor.py):**
- Wrap in try/except
- Re-raise P6SafeModeError
- Log and return False for other exceptions
- No retry loops

- `logger` from `src.utils`
- `P6SafeModeError` from `.exceptions`
- `immediate_click`, `immediate_type` from `.utils`
